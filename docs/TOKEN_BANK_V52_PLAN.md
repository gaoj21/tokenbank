# TOKEN_BANK_V5.2_PLAN：结论加固计划

> 目标：不改方案本体，把 v5.1 的结论做到审稿人打不穿。
> 前置文档：`experiment_findings_v5.md`（完整实验史）、`tokenbank_v51_summary.md`（当前对外总结）。
> 约束沿用：单种子、temp=0、seed=42（不做多种子；替代方案见 §6）。
> 主战场：GAIA(122) + MATH(400/500) 为廉价验证集；MuSiQue(1934) 只在必要时动。

## 0. 这份计划要解决什么

当前总结里有 **2 条硬结论** 和 **5 处会被打穿的地方**。

**硬结论（大概率保得住）**

- H1：等预算下，结构化治理 > 朴素固定管线（MuSiQue、FRAMES-16k、MATH-16k 均 ≥2.9σ）
- H2：语言化升级判据修复了纯 logprob 路由在计算密集任务上的反噬（MATH +18~22pp，~6σ）

**待加固的 5 处**

| 编号 | 问题 | 威胁到 |
|---|---|---|
| I1 | `ANSWER:` 格式指令同时是判题器的抽取锚点，Unc 没有 → 增益可能是抽取优势 | 检索型三个数据集的全部 SR claim |
| I2 | 24k 表里 MATH/FRAMES 的 Unc 仍是**全量**数字（500 / 824），被当作 test 数字并列 | 头条表 8/8 中的 2 格 |
| I3 | v5.1 自身零消融；M1/M3 的贡献主张全部引自 v5（另一套系统：logprob 路由 + max_tokens=768） | "机制净贡献"整节 |
| I4 | MuSiQue 99% 升 L2 → M2 在检索型任务上不做分流；§4"token 省在哪"对 FRAMES/MuSiQue 沉默 | "M2 是核心创新"的定位 |
| I5 | 池化失效解释（"conf=0 排池尾"）与排序公式 v_i=(1−conf)/c_i 矛盾（conf=0 应排池首） | M4 不作默认的唯一机制性理由 |

另有 2 处需要补齐而非修正：跨模型只验证了**问题**、没验证**修复**（X1）；全表无置信区间（R1）。

## 1. Phase R：零 GPU 离线重算（先做，全部基于现有 traces）

所有 R 项只读 `results/*.json` 与 `traces/*.jsonl`，不占卡。**建议一次性写成 `_v52_reanalyze.py`，输出统一的修订版主表。**

### R0 — trace 字段体检（前置，10 分钟）

确认以下字段在 v5.1 的 test/16k traces 里齐全，缺哪个就决定了后面哪项要退化成重跑：

- `f1`（R3 依赖）、`answer_snapshot`（R5 依赖，注意 ≤2000 字符截断是否影响末尾 `ANSWER:` 行）
- `escalation_level`、`stopped_by`、`flags_fired`（R4 依赖）
- 每轮 `prompt_tokens/completion_tokens/tool_output_tokens`（R4 的 token 口径）
- **Unc 臂是否同样落了这些字段**——这是最容易缺的

**出口**：一张字段可用性矩阵（配置 × 字段）。缺字段的项标记为"需重跑"并入 Phase C。

### R1 — 配对显著性与置信区间

- 每格 SR 报 **bootstrap 95% CI**（item-level resample，B=10000）
- 每个跨配置比较报 **McNemar 检验**（配对，同一批题）+ Δ 的配对 bootstrap CI
- 覆盖：8 格 NoPool vs Unc、4 格 NoPool vs Unified、以及后续所有消融对比

参考噪声量级（未配对粗算，配对会更紧）：

| 数据集 | n | 1 题 ≈ | Δ 的未配对 SE |
|---|---|---|---|
| GAIA | 122 | 0.82pp | ≈4.9pp |
| MATH | 400 / 500 | 0.25 / 0.20pp | ≈3.4 / 3.0pp |
| FRAMES | 659 | 0.15pp | ≈1.8pp |
| MuSiQue | 1934 | 0.05pp | ≈0.9pp |

**出口**：8/8 改写为"方向一致 8/8，显著 X/8"。GAIA 两格（+4.9pp≈1.0σ、+2.4pp≈0.5σ）能否被配对检验救回，以此为准。

### R2 — 题集对齐重算 【解决 I2】

- 在 **MATH test(400)** 子集上重算 Unc 与 v5 的 A6；在 **FRAMES test(659)** 子集上重算 Unc 与 v5 的 A0
- 16k 的 MATH 三臂当前都是 500（内部自洽），统一改成 test(400) 出表，或全表统一到 500 并注明含 dev
- 全表加 `n` 与 `split` 列；**跨题集比较一律不出现在正文表里**

**出口**：24k 的 MATH/FRAMES 两格给出同集数字。预期 MATH 的 18pp 翻不了盘，FRAMES 的 +3.7pp 有变数。

### R3 — EM / F1 双列 【I1 的第一道证伪】

- 主表每格并列 EM 与 token-F1
- 计算 **ΔEM 与 ΔF1 的差**（NoPool − Unc）

判读：

- ΔF1 ≈ ΔEM → 增益是真实的答案质量提升，I1 解除
- **ΔF1 ≪ ΔEM → 增益主要来自抽取/格式**，触发决策门 G1

### R4 — Pareto 图 + 分流审计 【解决 I4 的证据面】

- 每数据集一张 **SR vs 实际平均 token** 散点，标出所有配置（含 v5 的 A0/A4/A6），画出 Pareto 前沿
- 分流分布：每数据集的 L0/L1/L2 停留占比、`stopped_by` 分布、M1 触发率
- **按停留级别拆分 token**：L0/L1 的探路开销 vs L2 实际消耗，量化"99% 升 L2 时 L0+L1 是纯开销还是有效 draft"
- 补一张 FRAMES/MuSiQue 的 "token 省在哪" 分解，填上 §4 现在的空白

### R5 — 格式合规与抽取审计 【I1 的直接量化】

对每个配置 × 数据集，从 `answer_snapshot` 统计：

1. `ANSWER:` 命中率（Unc 臂预期显著低）
2. 退回 "last non-empty line" 抽取的比例
3. **按抽取路径分层的 EM 通过率**——同样一批题，命中 `ANSWER:` 的通过率 vs 退回的通过率
4. 人工抽样 30 条 Unc 判错样本，标注"真错 / 抽取失败"的比例

**出口**：给出"格式带来的 EM 增益上界"的一个数。若该上界能吃掉检索型数据集增益的 50% 以上，I1 坐实。

## 2. Phase C：廉价对照臂（prompt 级改动，各 1 次跑）

### C1 — `Unc+Fmt` 对照 【I1 的判决性实验】

- 配置：Unc 原样 + **仅**加 `ANSWER: xxx` 单行输出指令，其余一切不变
- 数据集：**GAIA(122) + FRAMES(659)**（检索型、受影响最大、题量可接受）；若 R5 显示 MuSiQue 抽取失败率同样高，再补 MuSiQue
- 预算：24k 与 16k

判读：

- NoPool − Unc+Fmt 仍保住大部分增益 → **头条表成立**，I1 解除
- 增益被吃掉大半 → **M3.4 从"治理机制"重新归类为"评测协议对齐"**，且 Unc+Fmt 成为新的正式基线

### C2 — `L2-only + L0draft` 对照 【I4 的判决性实验】

- 配置：跳过 L0/L1 的路由决策，强制所有题走 L2，但**仍先跑一次 L0 生成 draft** 喂进去
- 对照另一臂：`L2-only 无 draft`（= 纯固定管线 + M3）
- 数据集：MuSiQue-dev(483) + FRAMES(659)，24k

判读：三臂若同分 → **M2 在检索型任务上的价值是 draft 种子而非路由**，M2 的定位改写为"计算密集任务的分流机制 + 通用的 draft 种子机制"，并且系统可再简化一层。

## 5. Phase V：代码核查（不占卡）

### V1 — 池化排序的真实行为 【解决 I5】

在 `_budget_sweep_v2.py` 的 `run_m4_pool` 中核实：

1. ESCALATE 任务在 pass 1 结束时的 `conf` 实际取值（应为 0）与 `stopped_by` 取值
2. 按 v_i=(1−conf_i)/c_i 降序后，conf=0 任务的实际**排位分布**（理论上应在池首）
3. 是否存在第二处截流逻辑（如按 `c_i` 或按 pass-1 已花费过滤）把它们踢到池尾
4. 探针花费是否确实并入总账（影响 Unified 的 token 数与"省 8–12%"的口径）

**出口**：三选一——
(a) 确认排在池首 → §4 的机制解释是错的，须改写为"探针固定开销 + L2 带 draft 重跑的浪费"；
(b) 确认排在池尾 → 定位到第二处逻辑，说明是 bug 还是设计，修完重跑 Unified；
(c) 修复未生效 → 重跑所有 Unified 结果。

### V2 — Unc 基线的确切定义

逐条列出 Unc 相对 V5.1 少了什么（prompt 模板、格式指令、max_tokens、工具可用性、轮数上限、是否有 reviewer）。**当前"朴素固定管线、无任何治理机制"这句话不足以让人复现对照组。**这张对照清单直接决定 I1 的严重程度，也是审稿人第一个会问的东西。

## 6. 统计与出表规范（新主表的硬性要求）

1. 每格：`SR ± 95% CI (n=..., split=...)`，EM 与 F1 双列
2. 每个比较：McNemar p 值 + Δ 的配对 CI，不再出现裸点估计的大小关系
3. token：**实际平均 token（prompt+completion，含探针与工具输出）** 与预算帽分列；跨配置比较必须同时给 Pareto 图
4. 禁止跨题集比较；所有引自 v5 的数字标注判据版本与题集
5. **不做多种子的替代**：同一配置（建议 V5.1-NoPool × GAIA × 24k）重跑一次，报告 run-to-run 的**逐题翻转率**——vLLM 连续批处理即使 temp=0 也非严格确定。这个数字给出了"多小的差值不值得解释"的经验下界，成本一次跑，且能挡住"为什么单种子"的质疑
6. 术语：Unc 一律称"等预算基线"，不再出现"上界"

## 7. 决策门与叙事分支

| 门 | 触发条件 | 结论走向 |
|---|---|---|
| **G1** | R3 + R5 + C1 | ΔF1≈ΔEM 且 Unc+Fmt 未吃掉增益 → 头条表原样保留；否则检索型三格重写，主指标改 F1 或双指标，M3.4 归入评测协议 |
| **G2** | Ab3 + C2 | −M2 ≈ NoPool（MATH 除外）→ 标题从"语言化级联路由"改为"语言化升级判据 + 上下文经济学"，M2 定位为计算型分流 + 通用 draft 种子 |
| **G3** | X1 | 复现 → 核心创新跨模型；未复现 → claim 限定单模型 |
| **G4** | V1 | 分支 (a)/(b)/(c) 见 §5，决定 M4 是"机制性不适配检索型"还是"实现开销问题" |

**最坏情况下方案价值不塌**：即使 G1 判定检索型增益主要来自格式，H2（MATH +18~22pp 逆转）和全线 token 节省（−6.8%~−45.4%）依然成立，故事变为"跨任务类型的稳健性 + token 效率"，只是 SR claim 收缩到 MATH/MuSiQue。**先做 R 与 C1 正是为了在写作前知道自己站在哪个分支上。**
