Test thresholds in order with a betting test

1

Candidates

Thresholds t₁ > … > t_M, fixed before any label, from conservative to aggressive. Each gives a null: its mean loss exceeds ε.

2

Betting test

Bet that the mean loss is below ε. Wealth is a supermartingale under the null, so p = 1 / max W is valid.

3

Fixed sequence

Stop at the first threshold not rejected. Deploy the cheapest rejected one. No multiplicity correction needed.

Wj = ∏i≤j ( 1 + λi (ε − ℓi) ), λi set from the running variance of earlier losses

Following Learn-then-Test, every candidate threshold is a hypothesis that its risk exceeds the tolerance, and a threshold is deployable only if the calibration data reject it. We test the signed loss directly with a betting test: a gambler bets that the mean loss is below epsilon. Under the null the wealth is a nonnegative supermartingale, so by Ville's inequality one over its maximum is a valid p-value. The bet size follows the running variance, so the test adapts to how often stopping changes the answer at all. Testing in a fixed order needs no correction for the number of candidates.
